Profile

開発環境

プログラミングを2年と半年勉強し、ゲーム制作をしてきました。主な言語はC/C++でほかにもC#やPython、VBA、PHPなども学びました。 DirectXは11と12に触れOSはWindowsでMSVS2022を使いネイティブ開発をメインに勉強しています。

開発履歴

2年生に上がった当初に作成した2Dシューティングゲームです。 フレームワークは一年時に配布されたものを使用しました。

ゲームの特徴は、左クリックで発車した弾はプレイヤーが動かなければ動かない仕様になっており、反対の右クリックでの弾は プレイヤーが止まっていれば動く仕様となっています。 また自機や敵のテクスチャ、破壊時のSEやBGMをユーザが自在に変更できる機能を付けました。

2年時に作成したゲームです。 題材は「2.5D」でしたが、次作の3Dゲームのために3Dゲームに挑戦しました。 フレームワークは2年時の配布されたものを使用しました。

ゲームの特徴は、4つのモードがありそれぞれの評価基準があり、そこから金、銀、銅の3つで結果を出します。 鉱石であれば左クリックでつるはしを振りクリスタルを獲得し、右クリックで宝箱を取ります。 あっていればコンボ数が増加し、それに応じてUIの変化やSEの変化、ゲームスピードの変化が起こります。 1回のミスもしくは一定時間の経過でコンボがリセットされます。 ミスはテンションゲージを消費し無くなるとそこまでです。 また内部的には警告とマジックナンバーを0にしました。

2年時に作成した作品です。 この作品は来年の3年時に向けての技術習得用として作成しました。

ゲームの特徴は魚の主人公が障害物をよけながら右に進むものとなっています。 川では主人公の体力と酸素を回復することができます。 酸素が尽きるか回復が尽きるかでゲームオーバーとなってしまいます。 この作品ではオブジェクトリストを役割別にすることで当たり判定の対象を最小化したり、まとめて削除したりできるようにしました。 また可変フレームレート機能の追加や、ウィンドウ非アクティブ時の処理軽減、さらに外部ライブラリの自力での導入など行いました。これには CMakeを使用するなど大きな経験となりました。

Introduction

Pragmatic Hybrid Entity Component System（PH-ECS） は、 ゲーム開発において「純粋なECSでは得られない柔軟性」と 「ECSの分割する考えによるコードの明白さ」を両立させるために設計された 実用的ハイブリッドアーキテクチャ です。

このエンジンは、コンポーネントを単なるデータ構造ではなく、 データ構造＋補助メソッドとして扱います。

Concept – Pragmatic & Hybrid

1. Pragmatic（実用主義）

純粋ECSの理論美よりも「現場で使える設計」を優先。 コンポーネントはデータのみでなく、Getter / Setter / RenderImGui / Serialize / Deserializeのような 補助的な動作関数を持つことを容認します。
類似の設計として tiny-ecsがあります。

2. Hybrid（複合型）

内部はECS構造を採用しながら、エディタではコンポーネント指向的UIを提供。 開発者は「ECSとして実行し、コンポーネントとして編集する」という 双方向のワークフローを得られます。
同義の設計として Unity ECSがあります。

3. Editor Integration

すべてのECS要素はエディタと強く統合され、 コンポーネント追加・削除・DLLホットリロード・Pythonプラグイン実行などを 一元管理可能です。
